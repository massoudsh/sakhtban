## خلاصه‌ی صادقانه‌ی وضعیت

این ۲۶ فایل «طرح فنی + اسکلت کد کارکردی» هستند، نه فیچر production-ready کامل با تست روی سرور زنده.
یعنی:

- مدل داده، منطق کسب‌وکار اصلی (پارسرها، موتورهای rule-based) و API هر ۲۶ ایشو
  نوشته و اجرا شده‌اند (`backend/`)، و بخش‌های الگوریتمی با pytest تست شده‌اند
  (۱۲ تست سبز، بدون نیاز به دیتابیس).
- UI وب برای مهم‌ترین صفحات (`frontend/`) نوشته شده ولی build/run نشده (نیاز به
  `npm install` روی سرور، نه داخل این محیط).
- فرم لندینگ‌پیج (`docs/index.html`) حالا مستقیم به `POST /onboarding/pilot-lead`
  وصل است (#۸)؛ فقط آدرس واقعی سرور بعد از استقرار باید در `SAKHTBAN_API_BASE`
  تنظیم شود.
- **۲۵ ایشو از ۲۶ ایشو** مطابق متن دقیق خودشان در GitHub کامل و بسته شده‌اند
  (جزئیات هر کدام در فایل مربوطه). موارد enhancement آتی (نه بخشی از متن اصلی
  ایشو) که عمداً به بعد موکول شده‌اند: اتصال WhatsApp روی #۶ (issue فقط «وب یا
  تلگرام/واتساپ» خواسته بود)، رندر PDF روی #۱۴ (issue فقط summary خواسته بود).
- **یک ایشو صراحتاً باز مانده: #۲۲ (اپ موبایل بومی ثبت ایراد)** — این ایشو
  خودش یک رابط موبایل‌محور آفلاین‌فرست با گرفتن عکس/موقعیت روی پلان می‌خواهد؛
  API لازم (`backend/app/routers/qa.py`) آماده است ولی ساخت اپ موبایل واقعی
  نیازمند تصمیم استک (React Native/Flutter) و پروژه‌ی جدا است — خارج از دامنه‌ی
  این اسکلت بک‌اند/وب.
- migration واقعی دیتابیس (Alembic) باید روی سرور با PostgreSQL در حال اجرا انجام
  شود، نه داخل این محیط ابزار (فایل migration آماده و تست‌شده روی SQLite است).
